# Mandala goal tracking

Published November 24, 2026. See [the release record](releases/2026-11-24-mandala-tracking.md) for deployment IDs, production validation, backup and rollback commands.

Release branch: `codex/mandala-tracking-local`. The feature uses the existing private Planner gateway and task system. The isolated dummy preview is served at `http://127.0.0.1:13108`; visit `http://127.0.0.1:18109/preview` first to set its local-only session cookie. The fixture never calls Google or uses production tasks. Existing notes, calendar dimensions and task detail fields are retained.

## Interaction

The task and recurring-task popups have a small Network icon among their top-right header controls. It opens a searchable tile picker with hierarchical paths and an option to remove the assignment. It adds no form row. Linked tasks have a small matching marker beside the existing notes/project/recurrence indicators. On desktop it opens the tile's notes window; on mobile it remains an indicator.

Desktop Mandala popups have a small Target icon for tracking settings. Tracking is optional: frequency per calendar day/week/month/quarter/year, or an explicit review interval in days/weeks/calendar months. Automatic reminder generation defaults off, destination Back Log, strategy Distributed. Existing nodes start untracked. The small CirclePlus icon logs an activity or review immediately without a Planner task. A date and note can be corrected through the activity history pencil; ordinary daily notes never count. Removing a task-derived log explicitly undoes that occurrence's completion. Activity history is retained when a completed task is deleted.

The popup's compact summary expands to show the period, completed/planned/outstanding progress, linked pending tasks, history, linked task creation, snooze and pause controls. Custom dates are tucked behind a small calendar icon. Tracking fields share a compact 26px height; timezone stays saved in the background. Settings autosave after 650ms, with per-tile serialization so edits during a save survive its response. The existing top-right check flushes pending settings before closing; failed saves keep the popup open. There is no extra settings save button. A manually logged activity can be attached to an existing edited reminder without recording it twice. Untouched unscheduled redundant automatic reminders may instead be withdrawn, without manufacturing a completion.

Tile colors, sizes, connections and spacing remain unchanged. Filled check/pause circles, a dashed progress ring, a blue calendar and amber/red alert icons make the corner states easier to see. The task popup icon gains a faint accent background when linked. Tracked tiles show a small status icon and frequency progress inside their existing bounds. Completed and planned states differ. Previous missed periods are mentioned in the tooltip/details, without holding a new period permanently red. No aggregate parent scores, dashboards, analytics, external notifications or AI model calls are added.

## Accounting

The first browser initializes one saved IANA timezone; later devices cannot overwrite it. Monday–Sunday weeks and calendar months/quarters/years are evaluated in that timezone. Existing daily note dates are not rewritten. Activation and pause/resume prorate frequency targets by active calendar days in the current period, rounding up to whole activities. A pause ends at the beginning of its resume date. Voluntary logs remain possible during pauses. Review intervals restart from the resume date rather than treating paused time as neglect.

Activities are the source of completed counts. Task-based records use the actual completion timestamp/date. Incomplete dated tasks count as planned only for their own period and only if their date has not passed; unscheduled tasks do not count as planned but suppress more reminders. A task date earlier today still counts as planned. Moving a task changes coverage immediately. Unmet targets are not added to the next period.

Distributed opportunities are evenly spaced across active days, beginning with the first active day. Daily targets distribute opportunities within the local day; their Behind strategy looks ahead to the next half-hour boundary. Beginning-of-period strategy makes all current-period outstanding work eligible, one generated task per evaluation. Behind strategy compares coverage with expected progress through today's daily evaluation window, so even a once-per-period target can prompt on its final day. No tasks are generated for future or elapsed periods.

An unscheduled linked task blocks another reminder. Generated overdue tasks return to Back Log with identity/content retained; manual tasks retain their normal overdue behavior. Deleting an automatic reminder persists suppression until its next eligible opportunity (next period for Beginning; next day for a due review). Snoozing suppresses generation while tracking remains active. Pausing suppresses active evaluation and warnings without deleting history or creating catch-up debt. An explicit resume resets the review reference date.

Recurring definitions carry an optional assignment; new occurrences inherit it. Changes also update inherited pending occurrences, preserving explicit per-task overrides and completed history. Recurring completion is a server transaction, including direct use of the recurring control without an existing task row. One canonical occurrence is materialized when needed. A stable cycle identity prevents multiple task rows in one cycle from counting more than once; rescheduling preserves that identity. Materializing already-completed historical cycles does not backfill new activities.

## Persistence and synchronization

Apply migration `0020_mandala_tracking` before using this frontend. It adds three tables (`mandala_preferences`, `mandala_tracking`, `mandala_activities`) and nullable assignments/provenance fields on existing tasks/recurring definitions. The Mandala layout remains in its existing JSON document; notes remain in their separate table. Old tasks default to unlinked and not generated. Branch deletion removes its tracking/history and detaches surviving tasks rather than deleting them.

PostgreSQL writers serialize under the existing single-owner Mandala row lock. Task mutations, activity records and evaluations commit together. Unique activity source keys enforce one record per ordinary task or recurring cycle. Manual log requests retain an operation ID across retries. Tracking settings use revisions and reject stale saves rather than overwriting another device.

Evaluation runs on app opening, foreground/reconnect, every minute while open, and after relevant server mutations. The frontend refreshes task data and summaries after successful mutations. No separate scheduler service is introduced: while all app windows are closed, reminder generation waits until the next opening. The existing private gateway protects every new endpoint.

## Validation

Backend tests cover opt-in defaults, notes independence, completion/undo, actual completion dates, direct logs and corrections, future coverage, recurring inheritance/cycle identity, duplicate suppression, withdrawal protection, overdue handling, snooze, pause/prorating, reviews, timezone/calendar boundaries and branch cleanup. Browser tests in `tests/mandala-tracking-browser.test.mjs` exercise the compact picker, logging, linking, pause/resume, and mobile task completion. Like the existing notes browser suite, they require an explicitly marked disposable loopback fixture and never run against production.

Local validation passed: 66 backend tests, 16 existing client tests, Chromium and WebKit tracking/task-picker/mobile-completion tests, the existing Chromium/WebKit Mandala notes regression suite, scoped ESLint, TypeScript, and an isolated production build. Migration 0020 was applied to a copy of the previous model schema and downgraded again, preserving an existing task and verifying untracked defaults. These local tests did not modify production. Real PostgreSQL concurrency is enforced by the shared row lock and unique activity source keys; local accounting tests use isolated SQLite databases.

The published notes editor keeps its Enter/Shift+Enter behavior, native undo/redo, half-height blank lines and 12px nested hanging dash lists. The empty-note placeholder is removed. Scoped CSS makes the dash marker and spacing explicit in both browser engines; note parsing and editing logic are unchanged. Linked tasks, collapsed activity history and daily notes have separate labels in the expanded view.
