## Rollback

These are recovery instructions, not actions performed by the release.

### Frontend

Use Vercel's Rollback action to restore the previous deployment listed above. If Vercel account access is unavailable, revert the release commit on GitHub's `main` branch and push the revert to trigger the existing Vercel production integration. Identify the release commit by the message `Publish planner refinements and shared notepad`; revert that specific commit rather than resetting or force-pushing the branch. Wait for its Vercel status to succeed and verify the production alias.

### Backend

On the production server, run:

```bash
cd /opt/planner-api/backend
docker compose -f docker-compose.yml -f /opt/planner-api/backups/planner-20261024/rollback-compose.yml up -d --no-deps --no-build --pull never planner-backend
curl --fail --silent --show-error http://127.0.0.1:8001/health
```

The override runs the retained image directly with Uvicorn, bypassing its old Alembic startup command. This is intentional: the old image does not contain migration `0016_uncertainty_notepad`. The additive notepad table can remain in the database, preserving notes entered after release. Existing tables are unchanged by this release, so routine application rollback does not require restoring the database or dropping the new table.

The database archive is a disaster-recovery fallback. Restoring it would discard subsequent changes; preserve current data and obtain explicit approval before a full restore. Do not automatically run `alembic downgrade` or restore the archive as part of application rollback.

For a later forward deployment after using this override, rebuild the intended image and run normal Compose without the rollback override. Keep the old image and backup until the new release is accepted.
